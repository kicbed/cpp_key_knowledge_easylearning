## 3. 技术核对来源

### C++

- [C++ working draft](https://eel.is/c++draft/)
- [cppreference](https://en.cppreference.com/)

重点核对：

- 智能指针所有权语义。
- `std::move`、右值引用、完美转发。
- 容器复杂度和迭代器失效。
- `std::atomic` 与内存序。
- `std::mutex`、`std::condition_variable`。

### Linux / OS / 网络

- [Linux man-pages](https://man7.org/linux/man-pages/)
- [RFC 9293: Transmission Control Protocol](https://www.rfc-editor.org/rfc/rfc9293)

重点核对：

- `fork`、写时复制、文件描述符继承。
- `epoll` LT/ET 行为。
- TCP 三次握手、四次挥手、TIME_WAIT、可靠传输。

### MySQL / Redis

- [MySQL Reference Manual](https://dev.mysql.com/doc/)
- [Redis Docs](https://redis.io/docs/latest/)

重点核对：

- InnoDB 索引、事务、锁、MVCC。
- Redis 数据类型、`SET NX EX`、持久化、过期和淘汰。

## 4. 去重规则

多个来源常把同一知识点换问法，例如：

- “shared_ptr 原理”“智能指针区别”“循环引用”“引用计数线程安全吗”统一归到智能指针模块。
- “select/poll/epoll 区别”“ET/LT”“非阻塞 IO”“Reactor”统一归到 Linux IO 模块。
- “三次握手”“四次挥手”“TIME_WAIT”“粘包”统一归到 TCP 模块。
- “B+ 树”“聚簇索引”“最左前缀”“索引失效”统一归到 MySQL 索引模块。
- “缓存穿透/击穿/雪崩”“分布式锁”“RDB/AOF”统一归到 Redis 模块。

保留标准：

- 高频：多个来源反复出现。
- 可迁移：不同公司/岗位都可能问。
- 可讲清楚：能形成 1-2 分钟面试回答。
- 有深挖价值：能继续追问实现、边界和工程取舍。

剔除或弱化：

- 过度偏门、只在单篇面经出现的细节。
- 明显和 C++ 后端目标不匹配的 Java/前端特有问题。
- 只有结论但难以验证来源的内容。
- 容易诱导死记硬背但面试价值低的长列表。
