# 1. LRU Cache

## 目标

实现 `get` 和 `put` 都是 O(1)。面试官通常想看你是否能把“查找”和“维护新旧顺序”拆成两个数据结构。

## 数据结构

- `unordered_map<int, iterator>`：通过 key O(1) 找到链表节点。
- `list<pair<int,int>>`：维护访问顺序，头部最新，尾部最旧。

## 核心代码

```cpp
class LRUCache {
public:
    explicit LRUCache(size_t capacity) : capacity_(capacity) {}

    std::optional<int> get(int key) {
        auto it = map_.find(key);
        if (it == map_.end()) return std::nullopt;
        items_.splice(items_.begin(), items_, it->second);
        return it->second->second;
    }

    void put(int key, int value) {
        if (capacity_ == 0) return;
        auto it = map_.find(key);
        if (it != map_.end()) {
            it->second->second = value;
            items_.splice(items_.begin(), items_, it->second);
            return;
        }
        if (items_.size() == capacity_) {
            map_.erase(items_.back().first);
            items_.pop_back();
        }
        items_.emplace_front(key, value);
        map_[key] = items_.begin();
    }

private:
    size_t capacity_;
    std::list<std::pair<int, int>> items_;
    std::unordered_map<int, std::list<std::pair<int, int>>::iterator> map_;
};
```

## 为什么用 `splice`

`list::splice` 移动节点，不拷贝元素，迭代器仍指向同一个节点。访问一个 key 后，把对应节点移动到头部就是 O(1)。

## 面试易错点

- 容量为 0 时不能插入。
- 更新已有 key 时也要移动到头部。
- 淘汰尾节点时要先从 map 删除旧 key。

# 2. 阻塞队列

## 目标

生产者队列满时等待，消费者队列空时等待，并能优雅关闭。

## 关键点

- 队列由 mutex 保护。
- 等待用 `condition_variable`。
- 等待条件必须用 predicate，防止虚假唤醒。
- `close()` 要 `notify_all()`，否则线程可能永远睡眠。

```cpp
template <class T>
class BlockingQueue {
public:
    explicit BlockingQueue(size_t capacity) : capacity_(capacity) {}

    bool push(T value) {
        std::unique_lock<std::mutex> lk(mu_);
        not_full_.wait(lk, [&] { return closed_ || q_.size() < capacity_; });
        if (closed_) return false;
        q_.push(std::move(value));
        not_empty_.notify_one();
        return true;
    }

    bool pop(T& out) {
        std::unique_lock<std::mutex> lk(mu_);
        not_empty_.wait(lk, [&] { return closed_ || !q_.empty(); });
        if (q_.empty()) return false;
        out = std::move(q_.front());
        q_.pop();
        not_full_.notify_one();
        return true;
    }

    void close() {
        {
            std::lock_guard<std::mutex> lk(mu_);
            closed_ = true;
        }
        not_empty_.notify_all();
        not_full_.notify_all();
    }

private:
    size_t capacity_;
    bool closed_ = false;
    std::queue<T> q_;
    std::mutex mu_;
    std::condition_variable not_empty_;
    std::condition_variable not_full_;
};
```

## 面试怎么讲

这段代码的重点不是队列，而是关闭语义。`pop` 返回 false 表示队列已关闭且没有剩余数据；`push` 返回 false 表示关闭后不再接收新任务。

# 3. 线程池

## 面试官想看什么

- worker 生命周期。
- 任务队列同步。
- 析构时是否丢任务。
- 任务异常是否杀死线程。
- 返回值如何传回调用方。

## 简化设计

- `submit` 把任务包装成 `packaged_task`，返回 `future`。
- worker 不断取任务执行。
- 析构时设置 `stopped_ = true`，唤醒所有 worker。
- worker 在“已停止且队列空”时退出。

```cpp
class ThreadPool {
public:
    explicit ThreadPool(size_t n) {
        for (size_t i = 0; i < n; ++i) {
            workers_.emplace_back([this] { workerLoop(); });
        }
    }

    ~ThreadPool() {
        {
            std::lock_guard<std::mutex> lk(mu_);
            stopped_ = true;
        }
        cv_.notify_all();
        for (auto& t : workers_) {
            if (t.joinable()) t.join();
        }
    }

    template <class F, class... Args>
    auto submit(F&& f, Args&&... args)
        -> std::future<std::invoke_result_t<F, Args...>> {
        using Ret = std::invoke_result_t<F, Args...>;
        auto task = std::make_shared<std::packaged_task<Ret()>>(
            std::bind(std::forward<F>(f), std::forward<Args>(args)...));
        auto fut = task->get_future();
        {
            std::lock_guard<std::mutex> lk(mu_);
            if (stopped_) throw std::runtime_error("pool stopped");
            tasks_.emplace([task] { (*task)(); });
        }
        cv_.notify_one();
        return fut;
    }

private:
    void workerLoop() {
        while (true) {
            std::function<void()> task;
            {
                std::unique_lock<std::mutex> lk(mu_);
                cv_.wait(lk, [&] { return stopped_ || !tasks_.empty(); });
                if (stopped_ && tasks_.empty()) return;
                task = std::move(tasks_.front());
                tasks_.pop();
            }
            task();
        }
    }

    bool stopped_ = false;
    std::mutex mu_;
    std::condition_variable cv_;
    std::queue<std::function<void()>> tasks_;
    std::vector<std::thread> workers_;
};
```

## 扩展追问

- 队列无限增长怎么办：加容量、拒绝策略、调用方阻塞、降级。
- 任务执行太慢怎么办：监控执行时间、隔离慢任务、拆不同线程池。
- 线程数怎么定：CPU 密集接近核数，IO 密集通过压测确定。

# 4. 定时器小根堆

## 适用场景

连接超时、延迟任务、心跳检测。任务数量中等时，小根堆实现简单；海量定时器可考虑时间轮。

## 思路

堆顶永远是最近过期的任务。事件循环每次看堆顶是否到期，到期就弹出执行。取消任务可用 lazy delete：标记取消，等它到堆顶再丢弃。

```cpp
struct Timer {
    int id;
    int64_t expire_ms;
    std::function<void()> cb;
    bool cancelled = false;
};

struct TimerCmp {
    bool operator()(const std::shared_ptr<Timer>& a,
                    const std::shared_ptr<Timer>& b) const {
        return a->expire_ms > b->expire_ms;
    }
};

class TimerHeap {
public:
    int add(int64_t expire_ms, std::function<void()> cb) {
        auto timer = std::make_shared<Timer>();
        timer->id = ++next_id_;
        timer->expire_ms = expire_ms;
        timer->cb = std::move(cb);
        timers_[timer->id] = timer;
        heap_.push(timer);
        return timer->id;
    }

    void cancel(int id) {
        if (auto it = timers_.find(id); it != timers_.end()) {
            it->second->cancelled = true;
            timers_.erase(it);
        }
    }

    void runExpired(int64_t now_ms) {
        while (!heap_.empty()) {
            auto timer = heap_.top();
            if (timer->cancelled) {
                heap_.pop();
                continue;
            }
            if (timer->expire_ms > now_ms) break;
            heap_.pop();
            timers_.erase(timer->id);
            timer->cb();
        }
    }

private:
    int next_id_ = 0;
    std::priority_queue<
        std::shared_ptr<Timer>,
        std::vector<std::shared_ptr<Timer>>,
        TimerCmp> heap_;
    std::unordered_map<int, std::shared_ptr<Timer>> timers_;
};
```

## 易错点

回调执行时间不能太长，否则会阻塞事件循环。工程里常把回调投递到线程池，或限制每轮最多处理的定时器数量。

# 5. TCP 半包解析器

## 协议设计

用 4 字节大端长度字段 + body。读缓冲可能包含 0.5 个包、1 个包或多个包。

```cpp
class FrameDecoder {
public:
    void append(const char* data, size_t n) {
        buf_.append(data, n);
    }

    std::vector<std::string> decode() {
        std::vector<std::string> frames;
        while (true) {
            if (buf_.size() < 4) break;
            uint32_t len = readUint32BE(buf_.data());
            if (len > max_frame_) throw std::runtime_error("frame too large");
            if (buf_.size() < 4 + len) break;
            frames.push_back(buf_.substr(4, len));
            buf_.erase(0, 4 + len);
        }
        return frames;
    }

private:
    static uint32_t readUint32BE(const char* p) {
        return (static_cast<unsigned char>(p[0]) << 24) |
               (static_cast<unsigned char>(p[1]) << 16) |
               (static_cast<unsigned char>(p[2]) << 8) |
               static_cast<unsigned char>(p[3]);
    }

    std::string buf_;
    const uint32_t max_frame_ = 16 * 1024 * 1024;
};
```

## 面试易错点

- TCP 没有消息边界，不能假设一次 read 对应一次 send。
- 长度字段要限制最大值，防止恶意大包撑爆内存。
- `erase(0, n)` 对大缓冲可能有移动成本，高性能版可用读写下标环形缓冲。

# 6. KMP

## 关键理解

`next[i]` 或 `lps[i]` 表示模式串前缀和后缀的最长相等长度。匹配失败时，不回退主串指针，只回退模式串指针。

```cpp
std::vector<int> buildLps(const std::string& p) {
    std::vector<int> lps(p.size(), 0);
    for (int i = 1, len = 0; i < static_cast<int>(p.size()); ) {
        if (p[i] == p[len]) {
            lps[i++] = ++len;
        } else if (len > 0) {
            len = lps[len - 1];
        } else {
            lps[i++] = 0;
        }
    }
    return lps;
}

int kmpSearch(const std::string& s, const std::string& p) {
    if (p.empty()) return 0;
    auto lps = buildLps(p);
    for (int i = 0, j = 0; i < static_cast<int>(s.size()); ) {
        if (s[i] == p[j]) {
            ++i;
            ++j;
            if (j == static_cast<int>(p.size())) return i - j;
        } else if (j > 0) {
            j = lps[j - 1];
        } else {
            ++i;
        }
    }
    return -1;
}
```

## 面试怎么讲

暴力匹配失败后主串会反复比较；KMP 利用模式串自身的前后缀信息，让主串指针不回退，因此整体 O(n+m)。

# 7. 并查集

## 适用场景

连通性判断、朋友圈、岛屿合并、最小生成树 Kruskal。

```cpp
class DSU {
public:
    explicit DSU(int n) : parent_(n), rank_(n, 0) {
        std::iota(parent_.begin(), parent_.end(), 0);
    }

    int find(int x) {
        if (parent_[x] != x) parent_[x] = find(parent_[x]);
        return parent_[x];
    }

    bool unite(int a, int b) {
        int ra = find(a);
        int rb = find(b);
        if (ra == rb) return false;
        if (rank_[ra] < rank_[rb]) std::swap(ra, rb);
        parent_[rb] = ra;
        if (rank_[ra] == rank_[rb]) ++rank_[ra];
        return true;
    }

private:
    std::vector<int> parent_;
    std::vector<int> rank_;
};
```

## 易错点

路径压缩和按秩合并是两个优化。复杂度可近似看成常数，但严格是反阿克曼函数级别。

# 8. Trie 前缀树

## 适用场景

前缀匹配、词典查询、自动补全、敏感词前缀过滤。

```cpp
class Trie {
public:
    void insert(const std::string& word) {
        Node* cur = &root_;
        for (char c : word) {
            auto& next = cur->child[c];
            if (!next) next = std::make_unique<Node>();
            cur = next.get();
        }
        cur->end = true;
    }

    bool search(const std::string& word) const {
        const Node* node = findNode(word);
        return node && node->end;
    }

    bool startsWith(const std::string& prefix) const {
        return findNode(prefix) != nullptr;
    }

private:
    struct Node {
        bool end = false;
        std::unordered_map<char, std::unique_ptr<Node>> child;
    };

    const Node* findNode(const std::string& s) const {
        const Node* cur = &root_;
        for (char c : s) {
            auto it = cur->child.find(c);
            if (it == cur->child.end()) return nullptr;
            cur = it->second.get();
        }
        return cur;
    }

    Node root_;
};
```

## 工程取舍

字符集小且固定时可用数组提升速度；字符集大或稀疏时 `unordered_map` 更省空间。

# 9. 简化内存池

## 面试版目标

展示分配器思想，不要现场写过度复杂的工业级 allocator。重点讲清楚：批量申请、空闲链表、对齐、大对象回退、线程安全。

```cpp
class FixedBlockPool {
public:
    explicit FixedBlockPool(size_t block_size)
        : block_size_(std::max(block_size, sizeof(Node*))) {}

    ~FixedBlockPool() {
        for (void* chunk : chunks_) {
            ::operator delete(chunk);
        }
    }

    void* allocate() {
        if (!free_) refill();
        Node* node = free_;
        free_ = free_->next;
        return node;
    }

    void deallocate(void* p) {
        if (!p) return;
        auto* node = static_cast<Node*>(p);
        node->next = free_;
        free_ = node;
    }

private:
    struct Node { Node* next; };

    void refill() {
        constexpr size_t kBatch = 64;
        char* chunk = static_cast<char*>(::operator new(block_size_ * kBatch));
        chunks_.push_back(chunk);
        for (size_t i = 0; i < kBatch; ++i) {
            deallocate(chunk + i * block_size_);
        }
    }

    size_t block_size_;
    Node* free_ = nullptr;
    std::vector<void*> chunks_;
};
```

## 必须说明的限制

这个版本只适合同大小对象；没有处理严格对齐、线程安全、越界检测、重复释放检测，也不会把内存还给系统。面试里主动说出限制，比假装工业可用更可信。

# 10. 最小可用对象池

## 思路

对象池比内存池多一步：借出时构造或重置对象，归还时清理状态。为了避免忘记归还，可以返回带自定义删除器的 `unique_ptr`。

```cpp
template <class T>
class ObjectPool {
public:
    using Ptr = std::unique_ptr<T, std::function<void(T*)>>;

    template <class... Args>
    Ptr acquire(Args&&... args) {
        T* obj = nullptr;
        if (!free_.empty()) {
            obj = free_.back();
            free_.pop_back();
            *obj = T(std::forward<Args>(args)...);
        } else {
            storage_.push_back(std::make_unique<T>(std::forward<Args>(args)...));
            obj = storage_.back().get();
        }
        return Ptr(obj, [this](T* p) { release(p); });
    }

private:
    void release(T* p) {
        free_.push_back(p);
    }

    std::vector<std::unique_ptr<T>> storage_;
    std::vector<T*> free_;
};
```

## 易错点

这个简单版本不是线程安全的；如果对象持有外部资源，赋值重置未必足够，最好提供明确的 `reset()`。

# 11. 二分查找统一模板

## 推荐记法

用左闭右开 `[l, r)`，目标是找第一个满足 `check` 的位置。

```cpp
int lowerBound(const std::vector<int>& a, int target) {
    int l = 0;
    int r = static_cast<int>(a.size());
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (a[mid] >= target) r = mid;
        else l = mid + 1;
    }
    return l;
}
```

## 面试口诀

先定义答案是什么，再写 `check(mid)`。不要先写循环再凭感觉调边界。

# 12. 拓扑排序

## 适用场景

课程依赖、任务编排、编译依赖、检测有向图环。

```cpp
std::vector<int> topoSort(int n, const std::vector<std::pair<int, int>>& edges) {
    std::vector<std::vector<int>> g(n);
    std::vector<int> indeg(n, 0);
    for (auto [u, v] : edges) {
        g[u].push_back(v);
        ++indeg[v];
    }

    std::queue<int> q;
    for (int i = 0; i < n; ++i) {
        if (indeg[i] == 0) q.push(i);
    }

    std::vector<int> order;
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        order.push_back(u);
        for (int v : g[u]) {
            if (--indeg[v] == 0) q.push(v);
        }
    }
    if (static_cast<int>(order.size()) != n) return {};
    return order;
}
```

## 复杂度

每个点入队一次，每条边处理一次，时间 O(V+E)，空间 O(V+E)。

# 13. 最长递增子序列 O(n log n)

## 理解方式

`tails[len]` 表示长度为 `len + 1` 的递增子序列中，末尾元素的最小可能值。末尾越小，后续越容易接上新元素。

```cpp
int lengthOfLIS(const std::vector<int>& nums) {
    std::vector<int> tails;
    for (int x : nums) {
        auto it = std::lower_bound(tails.begin(), tails.end(), x);
        if (it == tails.end()) tails.push_back(x);
        else *it = x;
    }
    return static_cast<int>(tails.size());
}
```

## 易错点

`tails` 本身不一定是实际的 LIS，只用于维护最优末尾值。如果要求输出具体序列，需要额外记录前驱。

# 14. 回答代码题的固定结构

面试时写完代码后，不要只说“写好了”。建议按这个顺序收尾：

1. 解释核心数据结构。
2. 说明关键边界：空输入、重复元素、容量 0、异常/关闭。
3. 说明复杂度。
4. 主动指出工程版还需要补什么。

示例：

```text
这个 LRU 用 unordered_map 定位节点，用 list 维护访问顺序。
get 和 put 都是 O(1)，容量为 0 时直接忽略 put。
这版不是线程安全的，如果用于多线程缓存，需要在 get/put 外层加锁，或者做分片锁。
```
